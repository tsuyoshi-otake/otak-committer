# Rules (verified)

- [arch-test] Every `export` must be directly preceded by a line that is exactly `*/` (Architecture Property 14). A one-line `/** x */` fails; use multi-line JSDoc. — verified by: test:unit listed 7 undocumented exports and passed after the conversion (#10).
- [test-runners] The VS Code host suite discovers only `out/test/**`, `out/infrastructure/**/__tests__/**` and `out/__tests__/**`. Tests that import `vscode` at runtime belong in `src/__tests__/integration/`. The unit runner excludes them unless the name starts with i18n/bullet/pr/commit/issue. Type-only `vscode` imports are fine in unit tests. — verified by: `src/test/suite/index.ts` globs; `mapReduceSummarizer.test.ts` runs in neither suite (#9, #10).
- [build] `npm run compile` is `tsc --noEmit`. Run `npm run compile:test` before running mocha on `out/`. — verified by: stale `out/` results until compile:test was run (#10).
- [windows-tests] The VS Code test host runs Node 24.x, whose `fs.rmSync({recursive, force})` fails with EPERM on read-only files such as git objects. Node 26 does not. Remove temp repositories with `removeTempDirectory` from `src/test/helpers/temp-directory.helper.ts`. — verified by: Electron-as-Node 24.21.0 repro vs Node 26.2.0, and the host suite passing afterwards (#10).
- [git] To unstage specific paths, use `git --literal-pathspecs reset -q -- <paths>` and include both sides of a rename. This also works on an unborn branch. — verified by: real-repo tests in `src/services/__tests__/gitStaging.test.ts` (#10).
- [concurrency] When a cancellable command owns cleanup of shared state (for example unstaging), a re-run must await the aborted run's settlement before it reads that state. Use `restartLatest` from `src/utils/restartLatest.ts`. Aborting without awaiting leaves the cleanup racing the new run. — verified by: making the await a `void` in the compiled code failed the real-repo race test in `gitStaging.test.ts` (#10).
- [test-isolation] Host tests share one `vscode` module, and the file order from `glob` changes between runs. A test that replaces a `vscode.workspace` or `vscode.window` function must restore it in `teardown`. The host runner (`src/test/suite/index.ts`) fails the run and names any test that leaves `getConfiguration` replaced. — verified by: removing one restore in compiled output made the runner name both leaking tests and exit 1 (#10).
- [host-tests] If `npm test` ends with `Exit code: 1`, no mocha summary, and the newest `.vscode-test/user-data/logs/*/window1/exthost/exthost.log` ends with `received terminate message from renderer`, the test window was closed. It is not a test failure, so rerun without touching the window. — verified by: 2 such runs; the same code passed 3 other runs (#10).
- [commit-scope] When the working tree also holds another contributor's uncommitted work, stage only your own hunks and verify the staged tree alone. Run `git -c core.autocrlf=false checkout-index -a --prefix=<scratch>/`, link `node_modules` with a junction, then run compile, lint:ci and test:unit there. Delete the junction non-recursively (`[System.IO.Directory]::Delete`) before removing the folder. Expect fewer unit tests than in the working tree when that contributor's tests stay out. — verified by: staged-tree runs for #9 (406 vs 430) and #10 (500 vs 524).
- [git-identity] No git user is configured on this machine (`git var GIT_AUTHOR_IDENT` fails). Commit with the identity the existing history uses (`git log -1 --format='%an <%ae>'`), passed as `git -c user.name=… -c user.email=…`. — verified by: commits 57926ea, b0a495b and 8126e74.
- [vsce-package] When building the VSIX from an exported tree (checkout-index + fresh `npm ci`), use `vsce package --no-dependencies`. Without it, vsce 3.9.1 found no files ("Extension entrypoint(s) missing"). `node_modules` is in `.vscodeignore` and esbuild bundles the dependencies, so the contents are unchanged. — verified by: `vsce ls --no-dependencies` in the export matched `vsce ls` in the repo (41 files); the resulting VSIX had 43 entries including `extension/out/extension.js` (release 2.18.0).
- [release] Release by pushing a tag `vX.Y.Z` that matches package.json `version` and points at a commit on main. `.github/workflows/release.yml` builds one VSIX and publishes it in two independent jobs: Marketplace (`VSCE_PAT` secret) and Open VSX (`OVSX_PAT` secret). No registry token is needed locally. The local vsce store holds only publisher `otak`, and the az CLI account is the work tenant. To release an existing tag again, e.g. to a registry added later, run `gh workflow run release.yml --ref main -f tag=vX.Y.Z`. Both publish commands use `--skip-duplicate`, so a registry that already has the version is skipped. Publishing tools are pinned in `.github/release-tools`, with their own lockfile resolved with `--before` 7 days ago; the extension lockfile does not change. — verified by: run 37104627677 for v2.18.0 ("Published odangoo.otak-committer v2.18.0."); `.claude/goal-loop/openvsx-release/guard-test.sh` (tag/ref guard cases) and `mock-publish.mjs` (ovsx publish, then skip duplicate) (#11).
- [release-tools-audit] ovsx 1.2.0 asks for `@vscode/vsce` ^3.7.1, whose 3.x tree has 6 high advisories. Keep the npm `overrides` entry that points ovsx at the root vsce 4.x. It is safe because ovsx calls vsce only to package, and the workflow always passes a prebuilt `.vsix`. Before bumping ovsx, check `lib/publish.js` `doPublish` still skips `packageExtension` for a `.vsix`. — verified by: ovsx 1.2.0 source (`createVSIX` only in `packageExtension`); `npm ls` shows one vsce 4.0.0 (deduped); `npm audit` 0 vulnerabilities; mock registry publish passed (#11).
- [deps-audit] Security Scan runs `npm audit --audit-level=high` on the root lockfile with dev dependencies included, so a dev-only advisory fails it. Fix it by raising the `overrides` floor, or the parent that pulls the package in, then regenerate the lockfile with `npm install --package-lock-only --ignore-scripts --before=<7 days ago>`. `braces` ≤3.0.3 has no fixed version: keep chokidar 3 out of the tree (`@vscode/test-cli` ≥0.0.15 uses chokidar 5). For a package age check, take the registry name from `resolved`, not the install path, because npm aliases such as `string-width-cjs` are installed under their alias. — verified by: staged-tree `npm ci` and audit report 0 vulnerabilities, and `npm ls` shows no braces; test:unit 500 and host suite 498 passing; age check 347/347 (#6).
